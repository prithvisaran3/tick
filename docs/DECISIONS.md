## Production audit (branch fix/production-audit, 2026-11-05)
- Dart/Flutter floor is **Flutter 3.44 / Dart 3.12** (the user's installed toolchain), not the sandbox's 3.47. Analyze, tests and goldens run on 3.44.9; CI pinned to 3.44.9. `intl ^0.20.2` because `flutter_localizations` pins it.
- Google sign-in is **Supabase web OAuth (PKCE) in an ASWebAuthenticationSession**, not the native Google SDK: it removes the iOS client id, the reversed-client-id URL scheme and the bundle-id coupling (a free Apple account forces a custom bundle id). Server side verified from the sandbox that Supabase redirects to Google with `https://<ref>.supabase.co/auth/v1/callback` and Google accepts it.
- A custom 60-line Swift web-auth channel (`TickWebAuth.swift`) is used first because `flutter_web_auth_2` looks up its window through the app delegate, which is nil under UIScene; the plugin remains as the fallback. Untested on device (no Swift compiler here).
- Free Apple account: **no App Groups**. Widget snapshot is off unless `--dart-define=TICK_WIDGETS=true`; `TickWidget` was never added to the Xcode project; the App Intent hands data to the app through the app's own `UserDefaults` (`flutter.pendingAdd`).
- Day boundaries on the phone use the device time zone (the user is in America/New_York and iOS follows the system zone; loading the tz database at launch costs startup time). The **server** converts to America/New_York explicitly.
- Offline: snapshot at `<app support>/ledger_cache.json` (no tokens or secrets, capped at 1,200 purchases / 4 MB, atomic write, decoded off the UI isolate, keyed by user id, deleted on sign-out and Delete all data).
- Realtime bursts are coalesced to one refresh per 1.5 s; the Plaid first sync moved to background tasks and a per-page bulk insert. `plan()`/reconcile logic itself was not changed in this audit (the batched sync only changes how rows are loaded and written).
- Supabase migration `20261105000001_indexes_and_cleanup.sql` is written and **not applied**; `tools/db.py push` would apply it. The RLS test file was extended and run (it rolls back).
- API deploy: the changes are backward compatible and covered by the 127-test suite, but NOT deployed from this session (production deploy was not permitted). Deploy with `cd api && railway up --service tick-api --ci`, then run `python3 tools/e2e_deployed.py`.

## Cards, ideas and security (branch feat/cards-ideas-security, 2026-11-06)
- **Plaid slot burn, root cause** (Railway logs 2026-11-05 01:34:58): the `SESSION_FINISHED` webhook and the app's `POST /plaid/complete` both exchanged the same public token in the same second. Both saw no connection yet, both bumped `plaid_slots.used` (a read-modify-write), and the second Vault insert hit 409, which surfaced as "That didn't go through". Plaid created ONE Item (same `item_id` in all four lookups). Fix: an atomic claim on the link session (conditional PATCH), an idempotent exchange that returns the existing row, `tick_vault_upsert`, and links used = distinct `item_id`s in an append-only `plaid_items` table. The app client already never retried POSTs; there is now a test for it.
- **Local Postgres for migrations and RLS** (`tools/local_db.py`, with stubs for auth, vault, storage, pg_net and pg_cron). Migrations and the SQL suites are tested without touching the Supabase project, in the sandbox and in CI.
- **Totals come from SQL**: `tick_flows`, `tick_activity_page` (keyset on `occurred_at desc, id desc`, 40 a page) and `tick_months`, all SECURITY INVOKER. Demo mode and the signed-out guest ledger use a Dart mirror (`domain/flows.dart`) that a parity test (`flows_parity_test.dart`) checks against the same fixture as `supabase/tests/flows.sql`. The "Day" is the New York day on both sides (`etToUtc`/`etDay` in Dart, so it doesn't depend on the phone's zone).
- **Money rules**:
  - Internal transfers (`flow='transfer'`) and the Transfer category are neither spending nor income.
  - A positive amount on a card or loan that isn't a payment is a refund: it lowers spending, never income.
  - A loan payment from checking is `flow='bill'`, counted as cash out (a bill).
  - Fees and interest have their own category.
- **Transfer pairing** (`api/app/transfers.py`): same total within -1 to +5 days, closest first; one payment can cover 2–3 cards. An unmatched card payment stays a transfer only on strong evidence (Plaid's category, or issuer plus "payment" wording), because the card's purchases are already counted (Apple Card). Zelle to a friend is left alone unless my own account received it.
- **Liabilities**: requested as an `optional_products` entry when the link token is made. If Plaid refuses the product (plan not enabled), the token is made without it; creating a link token never creates an Item. `/liabilities/get` is called only for Items whose `products` include it, so an older Item is never silently upgraded to a billed product. All four target banks support Transactions and Liabilities (`docs/PLAID_INSTITUTIONS.md`, from the free metadata endpoints).
- **Safe to spend** subtracts card statements due on or before the next payday (and anything past due). When the bank doesn't share a due date, it subtracts the whole balance (conservative). It also subtracts a loan payment due before payday, unless a recurring bill already covers it.
- **Apple Card**: no FinanceKit. A Wallet card named "Apple Card" maps to one manual Apple Card account. The CSV import skips rows matching a live capture (same amount, similar merchant, ±2 days), and re-imports are idempotent (`external_ref`). Added `file_picker` (no third-party pods, iOS 14+) to choose the file.
- **Labs**: four ideas shipped behind Settings flags, all on by default: card-due guard, truly free, statement cycle plus utilisation heads-up, what if. Fifteen more are specced as tickets in `docs/IDEAS.md`.
- **Security**:
  - Capture tokens are now minted by the server (the app can no longer insert or rewrite them).
  - `anon` has no table or function privileges.
  - The Supabase session and PKCE verifier live in the Keychain (`flutter_secure_storage`, this device only).
  - Cache files get file protection complete and are excluded from backups through a small Swift channel.
  - JWTs need `iss`, `aud` and `role`, and a bad signature is never retried against the Auth server.
  - Logs are redacted and httpx URL logging is off.
  - No certificate pinning (rotation risk; reasoning in `docs/SECURITY.md`).
- **Not done by me on purpose**: Supabase Auth config changes (`tools/auth_config.py --apply`), the GitHub repo security settings (the session's GitHub access can't set them), deploys and `db push`. All are in NEXT.md and SECURITY.md §5.
- **Manual-step order**: `supabase db push` comes before `railway up`, because the new API needs the new tables. Every migration is additive, so the API that is running now keeps working against the new schema.

## Final polish (branch feat/final-polish)
- **Part 0 root cause**: PostgREST bulk inserts need identical keys per object; rows carried `tags` only when tagged, so pages mixing tagged and untagged rows (Discover 10/32, Bank of America 7/99; Chase and SoFi have none) failed with a 400 that `_safe_sync` swallowed. Details and the other findings: `docs/SYNC_DIAGNOSIS.md`. Diagnosed with the read-only `tools/plaid_doctor.py` against production (no Item created, nothing written).
- A connection is "Up to date" only once Plaid says the full history is loaded or the Item is older than 15 minutes; before that it says "Syncing your history…", and after 10 minutes without progress "Taking longer than usual" with the reason and a retry. This is the "never a forever-spinner" rule and it is a unit test.
- Manual pull-to-refresh calls `/transactions/refresh` best effort (rate-limited to the existing per-user limit; a refusal is ignored and the normal sync still runs).
- **Activity** is one continuous list across all months with a pinned month header (in, out, net under the active filters, from SQL) and day headers with the day's net. The month chips are gone; "Jump to month" lives in the filter sheet. Month-boundary handover plays a light selection tick. Rows use `cleanMerchant` ("Jpmorgan Chase Bank, Na" is "Chase"), a pending style, and swipe actions (Categorise, Split, Reviewed or Business) that are also VoiceOver custom actions.
- **Insights replaces Flows.** It answers "where is my money going and am I on track?" with: this month vs last at the same point (and the projection), where it went by category with the change since last month (tap into Activity filtered to it), top merchants (tap into Activity), subscriptions and price changes, and what is ahead until payday (card statements, loan, bills, safe to spend, per day). The spending-calendar heatmap was removed: it showed intensity, not amounts, and tapping a day went nowhere, so it didn't earn its place. Everything reads the shared money rules.
- **Navigation**: Today, Activity, (+), Insights, Tally. Ask Tick is an avatar button (top right of every tab) that opens a spring sheet. The profile avatar on Today opens Settings.
- **Haptic map** (one pattern, one meaning): selection tick = chips, toggles, tab changes and crossing a month boundary (system selection click, silent when Haptics is Off); confirm = `sort_right` (applied a sheet, committed a swipe); success = `price_weight` mid (import finished); landed/count-up/pop/price-weight/hold/tear/heartbeat keep their meanings; heartbeat is used when a Tally group squares up; errors use the system warning.
- **Card statement logic**: Plaid often leaves `last_statement_issue_date` empty and reports a minimum of 0 for "unknown". A statement counts as paid when the last payment is at least the statement balance and was made within 30 days before the due date (or after the statement date when known); owed beyond the statement is "new since it closed, due with your next statement"; a minimum of 0 is shown as "not shared by the bank". Safe to spend uses the same logic.
- **Statement import**: one flow for every bank, with detection from the file's own columns (never from what the user says), a preview with account picker, new vs duplicates and sample rows, an import that is ONE batch (`import_batches`, rows carry `import_batch_id`) so Undo removes exactly it, and a "tally marks" completion moment (success haptic). De-duplication: stable content refs for earlier imports, then amount + date ±2 days + similar merchant against Plaid rows and live captures on the same account (a Wallet capture without a merchant still counts within one day). PDFs are refused with a clear message (no PDF text extraction without a heavy dependency); noted in IDEAS. "Open in Tick" = `CFBundleDocumentTypes` (CSV, OFX/QFX via an imported UTI) + `SceneDelegate` overrides + a small inbox plugin; no App Groups. The Shortcuts action hands the file over the same way.
- **API JSON is decoded as UTF-8**: `http`'s `body` assumed Latin-1 when the server sent no charset, which turned "••1545" into mojibake in labels produced by the server.
- **Settings root**: profile header + 9 one-line rows in 4 groups (Security: Face ID lock, Privacy blur; Banks and cards: connections, capture token and Shortcuts, Import statements; More: Appearance and feel, Data, Labs, About and safety). Panic, delete-all, sign out, demo mode and AI status moved to About and safety. 9 rows is over the "about 7" guide, but each is a single line and removing any would hide something people look for.

## Part 6: Tally (decisions)
- **People, not accounts.** A friend is a row in `people` owned by me; nobody else signs in. Groups and 1:1 ("direct") tallies are owner-only tables with forced RLS and composite FKs (a group can only contain my people). Money is integer cents; "me" is a null person id on the server and `me` in Dart.
- **Splits**: equal (leftover cents go one each to the first people), exact (must add up, the sheet shows what is left), percent (must total 100) and shares, both via largest-remainder so shares always add to the total. `tally_save_expense` re-checks the sum in SQL, atomically.
- **Balances** per group, never netted across groups (a debt in one group does not cancel credit in another). Only `confirmed` settlements count. Simplify = biggest debtor pays biggest creditor; Python and Dart share vectors (`api/tests/data/tally_simplify.json`) and tie-break identically.
- **Tick never moves money.** "Settle up" records that a payment happened. If a Zelle row in Activity matches (amount, direction, name) the sheet offers it as a suggestion; nothing is linked until I tap.
- **Share link**: 32-byte random token, only its SHA-256 stored, expires in 1..90 days (app uses 30), revocable, max 5 live per group, rate-limited, shown once. The public page `/t/{token}` is read-only, escaped HTML, noindex, `no-store`, calm identical 404 for unknown/expired/revoked/malformed tokens. "I paid" on that page creates a *pending* settlement (capped, rate-limited) that never changes a balance until I confirm it in the app.
- **Copy**: Tally is the one playful corner ("All square ✓", "Nobody owes anybody."); errors and money problems stay plain.
- **Signature moment**: when a settle/confirm brings a group to zero, tally marks draw (four strokes, Volt slash) with the heartbeat haptic; Reduce Motion shows the finished marks.
- **Today** shows "You're owed $X" only when something is owed to me (the sum of positive group balances).
- **Not built (deliberately)**: Tally reminders by SMS/push to friends (would need a messaging service; "Remind" is a share sheet with the link), receipts per expense (column exists, no UI), multi-currency.
