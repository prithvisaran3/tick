| B-02 | `services/auth.dart` (old), `Info.plist:CFBundleURLSchemes`, `Flutter/*.xcconfig` | Google sign-in does nothing / errors | The native Google SDK path needed (a) an iOS OAuth client whose **bundle id equals Runner's** (a free Apple account forces a changed bundle id), (b) the reversed client id injected as a URL scheme from a git-ignored `Local.xcconfig` (`$(GOOGLE_REVERSED_CLIENT_ID)` collapsed to an empty scheme if `setup_local.py` was not run), (c) three client ids via `--dart-define`, (d) nonce handling. Tick now ships its own 60-line scene-safe channel (`ios/Runner/TickWebAuth.swift`, anchor = the key window of the connected `UIWindowScene`) and only falls back to the plugin if that channel is missing; it is used for both Google sign-in and Plaid Hosted Link. **Verified from the sandbox:** Supabase `/auth/v1/authorize?provider=google` redirects to Google with the correct `redirect_uri` and Google serves the sign-in page (no `redirect_uri_mismatch`) | fixed; end-to-end tap needs the phone |
